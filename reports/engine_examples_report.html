Process Engine Examples

The engine reads an event log, works out the process map, drafts which resources limit the process, simulates it, and checks the simulation against the log. This page shows it on three logs.

The first two logs were generated with known settings, so the right answers are known. The ED log is also synthetic. These results show the method works. They say nothing about a real hospital.

How to read the checks. Pass: the simulation is within 5% of the log (or within 0.1 minute for times). Within noise: more than 5% off, but the gap is smaller than the spread between repeated simulation runs, so it cannot be called a real miss. Miss: a gap larger than that spread.

How the engine works

Follow one log, the coffee shop, through every step. A log is just a table of events. These are the first rows for one customer:

StepWhat the engine doesOn the coffee-shop log
1. ReadPuts each case's events in time order and measures time in minutes from the first event.47,351 customers, 7 different activities.
2. Find the process mapCounts, for every step, which step comes next and how long the gap is.After "Arrive", 42,981 customers (90.8%) go to "Order start" and 4,370 (9.2%) go to "Walked away".
3. Draft the resourcesWhen the same resource label sits on two consecutive events, it treats them as a start and an end of one use. Capacity is the most uses that ever overlapped."cashier" on Order start and Order end: capacity 1. "barista" on Prep start and Prep end: capacity 2.
4. FitLearns arrival rate by hour and weekday, how long each step takes, and how long people wait before giving up.About 55 arrivals an hour at breakfast, 22 mid-morning. Customers who walk away have waited 5.97 minutes on average.
5. SimulateCreates customers at the fitted rate. Each one follows the map, draws step times from the fitted distributions, and joins a real queue whenever the cashier or both baristas are busy.60 simulated days, repeated 4 times with different random numbers.
6. ValidateMeasures the simulation and the log with the same code and compares the numbers.20 of 20 measures within 5%.
The key idea: waits are not copied from the log. In the log, the gap between "Order end" and "Prep start" averages 4.0 minutes, and that is mostly waiting for a barista. The engine does not replay that gap. It leaves it out and lets a real queue produce the wait in the simulation. That is why you can ask what-if questions, such as adding a third barista, and get a different wait.

What the engine cannot work out alone, such as beds held across several steps, staffing by shift or work the log never records, goes in a short setup file. The emergency department example shows this.

What did not match

  • Physician wait needed one fix. The log only shows physicians busy during the first assessment. Reassessment work is invisible, so the first run gave a 3 minute wait against 27 in the log. The engine now lets you declare that hidden work and calibrate it. After calibrating, the wait matches (25 against 27 minutes).
  • Time in the ED runs 12% long on average, and about 19 to 29% long for low-acuity patients.
  • More patients leave unseen in the simulation (6.7% against 4.4%), and the ED bed wait is longer (13 against 10 minutes). Both are within the spread between runs.
  • The ward stay is an input. It was set from the earlier ED model, so wait for a ward bed is not an independent check.

Limits

  • The next step depends on the current step and the patient's class, not on earlier history.
  • When the engine drafts capacity from a log, it uses the peak number of overlapping uses. If staffing changes by shift, that must be supplied.
  • A resource held across several events, or never released in the log, needs the setup file. The ED bed and the ward are both examples.
  • Hidden work is an assumption, calibrated to one measure. It should be checked against others.
  • Batching, preemption, and needing several resources at once are not modelled.
  • Not built yet: an AnyLogic export, a what-if command line, and an automatic report. The Python call for what-ifs works.
